# Форма заявок, вопрос деканату и уведомления — 20.11.2026

Владелец запросил оформить выбор файла, исправить отступы стрелок в форме и сделать прямой вопрос деканату без заявки. Следующим экраном отдельно выбрал «Уведомления». Это согласованный объём изменений интерфейса; другие экраны не подключались.

## Форма

Вместо системной кнопки — «Выбрать файл» в существующем стиле secondary. Имя файла или «Файл не выбран» отображается рядом и переносится при нехватке места. Нативный input скрыт, но вызывается доступной с клавиатуры кнопкой; типы, лимит и серверная антивирусная проверка сохранены. Все select в форме получают одинаковый шеврон с отступом 16 px справа и 44 px под него. Новые CSS-правила ограничены .request-form. Шрифты, сетки и оформление остальных форм не менялись. Для показа есть адрес /#requests/new, открывающий форму после загрузки справочников и входа студента.

## Вопрос деканату

Кнопка открывает отдельное окно переписки, не создаёт appointment или черновик. Сотрудники выбираются сервером через students.facultyID → faculties.deaneryID → deanery_staff → действующий accounts DEAN и активный employers. При отсутствии назначений показывается пустое состояние без вымышленного адресата. Факультет/адресат не задаётся параметрами запроса контактов.

Используется существующая MongoDB-модель личных диалогов. До первой отправки выполняются только чтения; при отправке открывается или повторно используется уникальный диалог двух аккаунтов и сохраняется текст. Переписка сохраняется после закрытия окна/повторного входа. У деканата появился раздел «Вопросы студентов» для чтения и ответа; его общие демонстрационные метрики скрыты. Общий раздел «Чаты» пока не подключается этой задачей.

Добавлены GET /messages/deanery-contacts (только STUDENT) и GET /messages/conversations/{id}/participants (только участник собственного действующего диалога). Выдаются только accountID/displayName/role, без email/паспортных данных. В списке диалогов эти же безопасные имена приходят необязательным members; PostgreSQL запрашивается один раз на страницу, клиент не делает отдельный запрос для каждого диалога. Сохранена совместимость со старым ответом без members. Недействующий участник закрывает страницу согласно прежнему контракту; ADMIN не читает чужие диалоги.

Обновление открытой переписки — раз в 10 секунд, списка деканата — раз в 15 секунд только в видимой вкладке. Пустой текст запрещён, предел 10 000 символов, повторное нажатие блокируется. Не выполняются автоматические повторы отправки сообщения после сетевой ошибки: MongoDB и PostgreSQL не образуют общую транзакцию, а запись сообщения и updatedAt — отдельные операции. При неопределённом результате интерфейс предлагает обновить историю перед повтором. Сообщения отображаются обычным текстом React, без HTML-вставки. Автоматическая отметка прочтения переписки пока не добавлялась; не выдаётся ложный статус «прочитано».

Прямая ссылка на вопрос: /#deanery-question. Для деканата: /#dean-messages после входа соответствующей ролью. Новых таблиц, коллекций или миграций нет. Глобальный согласованный контракт личных диалогов между аккаунтами не ограничивался факультетами; ограничение своего факультета применяется именно к подбору контактов деканата.

## Уведомления

Существующий компонент использует /notifications целиком с пагинацией и /profile/me. Название, текст, дата по Москве, непрочитанность и личная группа — из API. Демонстрационный массив удалён. Исходные теги/классы/стили компонента сохранены.

Нажатие отмечает собственное уведомление прочитанным через PATCH /notifications/{id}/read; переходы ведут в подключённые разделы расписания, заявок, дедлайнов и успеваемости. Для неподключённых целей показывается действительный текст, без перехода на демонстрационный экран. «Прочитать все» обновляет непрочитанные записи не более чем тремя параллельными запросами, после чего перечитывает серверный список. Частичная ошибка не маскируется успехом. Сервер сохраняет первоначальный notificationReadAt через COALESCE, повтор не меняет дату. Индикатор непрочитанного в оболочке получает актуальное значение. Прямая ссылка /#notifications.

## Проверка

39 проверок клиента/моделей/форм/сохранения оформления, TypeScript/Vite, ESLint, Go tests/vet. Локальные PostgreSQL/MongoDB проверяют принадлежность диалога, отправку/получение и безопасные имена; контакты факультета и запреты других ролей; личные уведомления, чужой доступ и устойчивость времени прочтения. Тестовая MongoDB создаётся отдельно и удаляется после проверки. Облачный read-only загрузчик для двух студентов и деканата проверяет действительные уведомления/контакты/списки; вопросы реальным сотрудникам не отправлялись, прочтение облачных уведомлений тестами не менялось.

При проверке обнаружен остановившийся Vite: он восстановлен на 127.0.0.1:5173. Go API перезапускается с облачными подключениями; ошибки теста из-за недоступности порта не выдаются за ошибки данных. Контракты синхронизированы в основном OpenAPI, встроенной документации и messages-openapi.yaml.

Браузерная автоматизация ранее недоступна. По разрешению владельца результаты открываются через open в Chrome; проверки HTML не заменяют визуальной приёмки. После показа ждать отзыва по форме, вопросу деканату и уведомлениям, не менять следующие экраны без выбора владельца.
