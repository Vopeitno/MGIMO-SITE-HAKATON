## Выполненные проверки

- `go test -race ./... -count=1` с переменными трёх интеграционных наборов: 35 тестов верхнего уровня, 92 результата с подтестами, без ошибок. Это не число уникальных пользовательских сценариев; общая проверка API содержит 12 основных сценариев.
- `go vet ./...` — без замечаний.
- `govulncheck` после обновления Go и зависимостей — известных уязвимостей не найдено.
- `node --test frontend/api.test.mjs` — 6 проверок клиента с подменой сетевых ответов.
- `node --test frontend/api.integration.test.mjs` — 1 сквозная проверка настоящего клиента при запущенных Vite и Go API.
- `npm run build`, `npm run lint`, `git diff --check` — успешно.

## Что проверками не подтверждено

1. Визуальная работа в браузере и на телефоне: браузерный инструмент вернул недоступность подключения. Проверка HTTP-клиента не заменяет проверку настоящей политики cookie браузера.
2. Положительная антивирусная проверка документа: ClamAV в текущем окружении не установлен. Сервер отклоняет загрузку, когда сканирование недоступно.
3. Работа в Supabase/MongoDB Atlas, лимиты бесплатных проектов, HTTPS, доступность из России, публичный хостинг и инфраструктурная отказоустойчивость: владелец отложил создание облачных проектов.
4. Сценарии без согласованных контрактов: почтовая выдача/восстановление доступа, форма абитуриента, изменение анкеты, аватары и дополнительные сервисы. Для `subjectStudentID` не задан перечень разрешённых типов обращений; сервер отклоняет такое создание с 422 до согласования списка.
5. В интерфейсе пока нет отдельных форм для всех серверных операций: передачи обращений, новых оценок, экзаменационных результатов, редактирования расписания/курсов/новостей. Основные операции доступны через API; актуальная карта подключения находится в `frontend/INTEGRATION.md`.
6. Отправка сообщения и обновление даты диалога не образуют общую транзакцию; ограничение и риск повторной отправки описаны в `architecture.md` и контракте сообщений.

Начальная схема и доступность маршрутов не означают готовность всех расширенных пользовательских сценариев. Следующая внешняя стадия — создание отдельных бесплатных облачных проектов и проверка развёртывания; по текущему решению владельца работа остаётся локальной.
