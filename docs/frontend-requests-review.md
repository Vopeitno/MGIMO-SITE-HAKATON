# «Заявки»: серверный список и отправка

20.11.2026 владелец выбрал «Заявки» следующим экраном. Сохранены исходные карточки, сетки, форма, классы и CSS. Подключены API и существующие черновики; новых таблиц/атрибутов БД не добавлялось.

## Что работает

- Полный список собственных обращений `/requests`, фильтры по статусам, серверные UUID, дата по Москве, актуальные имя/группа/уведомления. `localStorage student-requests` и демонстрационный массив из активного приложения удалены.
- Справочники типов `/requests/types?activeOnly=true` и корпусов `/buildings` загружаются с сервера. Ошибки не подменяются статичными вариантами.
- Новая заявка: тип обращения, электронный документ или получение в деканате, реальный корпус выдачи, комментарий, необязательное вложение. Способ получения записывается явным префиксом в appointmentDescription, поскольку отдельного атрибута в схеме нет. buildingID бумажного документа сохраняется отдельно в существующем поле appointment.
- Сначала создаётся/обновляется принадлежащий пользователю серверный черновик. Вложение загружается и проверяется до отправки черновика. Неуспешная загрузка не переводит заявку в рабочую очередь и не показывает успех. Черновик при ошибке остаётся на сервере; автоматическое удаление неподтверждённых черновиков не выполняется.
- Отправка черновика создаёт заявку и историю в транзакции, передаёт вложение и корпус, переводит черновик в submitted. Сигнал успеха и номер показываются только после подтверждения сервера. Список обновляется, фильтр переключается на «Все».
- Для новых отправок appoinmentID равен UUID черновика. Повторный submit по контракту возвращает 409, а клиент читает уже созданную собственную заявку по этому известному ID вместо создания дубля. Блокировка кнопки защищает от повторного нажатия в процессе запроса. При потере ответа черновик позволяет восстановить результат повторной попыткой; после закрытия формы список также показывает созданную заявку.
- Карточка читает `/requests/{id}` и всю `/history`, отображает введённые данные, полный номер, действительный статус, дату, корпус, историю с причинами и скачивание доступного вложения. Вымышленные ожидаемые даты готовности убраны: такой атрибут отсутствует в БД.
- Быстрое создание с «Сегодня» ведёт в подключённый раздел заявок. Прямая ссылка `/#requests` сохраняется после входа.

## Дополнение API без миграции

`POST /requests/drafts/{appointmentDraftID}/submit` допускает необязательное JSON-тело `{ "buildingID": "UUID или null" }`. Другие поля отклоняются, UUID проверяется, FK проверяет существование корпуса. Старые запросы без тела сохраняют прежнее поведение. Новое сопоставление ID описано в обоих OpenAPI-источниках. Ролевые и объектные проверки остаются серверными; студент не может менять автора, статус или обращаться к чужой заявке.

## Файлы и антивирус

Локально установлен ClamAV 1.5.5; официальные main/daily/bytecode загружены через freshclam и проверены самим ClamAV. В .env заданы CLAMSCAN_PATH и CLAMAV_DATABASE_DIR. Базы и локальный конфигурационный файл находятся в gitignored `backend/.local/`; в репозиторий не попадают. Установку выполнял Homebrew с необходимыми зависимостями.

PDF, PNG, JPEG, DOCX, до 10 МБ: проверяются содержимое, расширение, ограничения изображений/архива и антивирус. Видео/исполняемые файлы не принимаются. Файлы получают случайное имя и права 0600 в закрытом UPLOAD_DIR, выдаются только через авторизованный API. Сканирование ограничено двумя процессами и таймаутом 20 секунд. Занятость/ошибка сканера явно возвращается; проверки не обходятся. Каталог файлов и сигнатур нужно сохранять и обслуживать при выборе будущего хостинга, обновление баз — freshclam.

Проверен настоящий чистый PNG: загрузка в черновик, отправка, скачивание с побайтным сравнением, запрет скачивания другим студентом. Стандартный безвредный тест EICAR обнаружен установленным движком; временный тестовый файл удаляется после проверки.

## Проверки и границы

31 проверка клиента/моделей/сохранения исходных тегов, классов и стилей, TypeScript/Vite, ESLint, Go tests/vet и согласованность контрактов проходят. Изолированная PostgreSQL проверяет создание/статусы/права/конкурентность/откат, корпус выдачи, отсутствие дубликатов и реальный ClamAV. Настоящий загрузчик клиента проверен на облачной БД для двух студентов: список/справочники/карточка/история и отказ в доступе к чужой заявке. Новых обращений в облачную рабочую очередь тесты не отправляли; изменялись только временные сессии, завершённые logout.

Браузерная автоматизация ранее недоступна; по разрешению владельца результат открывается командой open в Chrome. HTML/API проверки не заменяют визуального отзыва. После открытия ждать отзыва по «Заявкам», следующие экраны не менять без выбора владельца.
