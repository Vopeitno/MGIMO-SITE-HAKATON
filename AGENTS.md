
# Цифровой деканат будущего — MGIMO

## Контекст
Проект хакатона: веб-приложение цифрового деканата для студентов и сотрудников университета.

## Источники требований
Перед реализацией функциональности изучи:
- docs/requirements.md — техническая документация
- docs/database.dbml — схема базы данных
- docs/openapi.yaml — контракт API

## Правила разработки
1. Соблюдай техническую документацию.
2. Не изменяй существующие сущности БД и их атрибуты без согласования.
3. Соблюдай соответствие API и базы данных.
4. Реализуй разграничение прав на сервере.
5. Учитывай роли STUDENT, TEACHER, SUPPORT, DEAN и ADMIN.
6. Не добавляй функциональность, противоречащую требованиям.
7. После изменений проверяй работоспособность кода и тестируй возможные сценарии, которые подойдут лучше всего для той или иной реализации, чтобы сразу их исправить или убедиться, что все работает хорошо. Составляй себе acceptance criteria и по ним проводи тестировку разработанной реализации.
8. Перед существенными архитектурными изменениями сообщай о них и делай только после согласования.
9. frontend вообще не трогай и не изменяй, в крайнем случае, при разработки части backend можно добавить то чего не хватает, но максимально в том же стиле, в котором сейчас находится дизайн веб части.
